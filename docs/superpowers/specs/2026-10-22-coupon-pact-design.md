# 식권장부 — 설계 문서

- 작성일: 2026-10-22
- 디자인 원본: `design/coupon-pact.pen` (pen.dev, MCP로만 열람 가능)
- 표기: **(Claude 판단)** = 사용자가 직접 정하지 않고 Claude가 정한 부분

## 1. 무엇을, 왜

동료끼리 식권(1장 = 10,000원 고정)을 주고받은 기록을 남기고, 누가 누구에게 몇 장 갚아야 하는지 한눈에 보는 웹 서비스.
지금은 기억이나 메신저에 의존해서 "내가 줬나, 받았나"가 흐려진다. 기록을 남기고 순잔액을 자동으로 계산해 주는 게 목적이다.

- 메인은 재미있는 대시보드(엔터테인먼트 느낌), 이력은 은행 앱처럼 차분하게.
- 프로토타입 단계. 소수 인원의 사내 사용을 가정한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 식권 주기를 몇 번의 탭으로 끝내고 즉시 반영.
- 사람 쌍(pair)별 순잔액으로 "누가 누구에게 몇 장"을 정확히 보여주기.
- 이력 조회·수정·삭제, 필터, 무한 스크롤.
- 관리자만 회원 추가·수정·삭제. 사번+비밀번호 로그인, 본인 비밀번호 변경.
- 모바일·데스크톱 반응형.

**비목표**
- 금액 입력(1장 = 10,000원 고정, 금액 필드 없음).
- 비밀번호 찾기/관리자 비밀번호 초기화, 회원 가입, 알림, 그래프.
- 다크 모드.

**반목표 (돌아가도 실패인 것)**
- 순잔액이 틀리게 보이는 것(상쇄 누락, 방향 뒤바뀜).
- 글이 많고 부제가 남발되는 "AI스러운" 화면.
- 비밀번호 평문 저장.

## 3. 사용자가 정한 것

- **잔액 규칙**: 두 사람 사이 주고받은 장수를 상쇄해 순잔액만 표시. A→B 3장, B→A 1장이면 "B가 A에게 2장".
- **메인**: 사람별 요약 — 각 사람(빚진 사람)마다, 그 사람이 갚아야 할 상대 목록. 상대는 프로필 아래 작게 이름과 사번. `전체 / 나` 전환. "식권 쏘기"로 검색해서 바로 주고 즉시 반영.
- **이력**: 컬럼 `준 사람 | 받은 사람 | 일자(YYYY-MM-DD HH:MM)`. 각 행 수정 가능. 필터는 기간·준 사람·받은 사람 + `나만` 보기. 페이지네이션 없이 오늘 기준 최근 1개월이 먼저 나오고, 스크롤하면 이전 기록이 이어서 로드. 상단에 "나"의 빚 요약.
- **마이페이지**: 프로필 사진 변경, 이름 변경. 비밀번호 변경.
- **계정**
  - 로그인은 사번 + 비밀번호. 관리자는 아이디 칸에 `admin`.
  - 관리자 계정: `admin` / `admin1234!` (최초 시드).
  - 일반 회원 초기 비밀번호 `0000`. 로그인 후 본인이 변경. 기능은 "비밀번호 변경"까지만.
  - 비밀번호는 단방향 해시로 저장.
  - 회원 추가·수정·삭제는 관리자만.
  - 회원을 삭제해도 그 사람과 주고받은 기록·잔액은 남는다. 로그인만 막힘.
- **권한**
  - 관리자: 회원·기록 모두 추가/조회/수정/삭제 가능. 기록의 날짜 수정은 관리자만.
  - 일반 회원: 기록 삭제 불가, 내용(준 사람·받은 사람·날짜) 수정 불가. 잘못된 기록은 **철회**한다. 철회는 그 기록의 준 사람과 받은 사람 둘 다 할 수 있고, 누가 철회했는지 남기고 보여준다.
- **메모**: 나만 보는 개인 메모. 기록과 별도 테이블. 다른 사람(관리자 포함)은 볼 수 없다. 메모가 있으면 기록 행 아래에 보이고 토글로 접고 펼친다.
- **이력 검색**: 메모 내용까지 포함한 텍스트 검색.
- **사번**: 대시(`-`) 등 문자 종류 제한 없음. 최대 12자는 **입력칸(`maxLength=12`)에서만** 막고, 서버/DB에는 길이 제한을 두지 않는다.
- **디자인**: 흰 배경, 은은한 회색 구분선, 포인트 빨강, 한국어 UI, 복잡한 그래프·장식 없음. 확정 디자인은 `design/coupon-pact.pen`.

## 4. 화면과 동작

디자인 파일의 프레임 이름 기준. 모바일(`M ·`)과 데스크톱(`D ·`) 각각 존재.

### 4.1 로그인 (`M · 로그인`, `D · 로그인`)
- 필드: 사번(관리자는 `admin`), 비밀번호(보기 토글). 사번 입력은 `maxLength=12`.
- 안내 한 줄: "처음 비밀번호는 0000이에요".
- 실패 시: "사번이나 비밀번호가 맞지 않아요" (어느 쪽이 틀렸는지 구분하지 않음).
- 로그인 성공: 일반 회원 → 메인, 관리자 → 회원 관리.
- 삭제된 회원은 로그인 불가(실패 메시지는 동일).

### 4.2 메인 (`M · 메인`, `D · 메인`)
- 상단 "내 잔액": 받을 식권 N장 / 갚을 식권 M장, 그리고 "다 정산하면 ±X원"(= (N−M)×10,000).
- "식권 쏘기" 버튼 → 모바일은 바텀 시트(`M · 식권 쏘기 시트`), 데스크톱은 왼쪽 열에 인라인 검색.
  - 이름 또는 사번 부분 일치 검색. 본인·관리자·삭제된 회원 제외.
  - 각 사람 옆 현재 상태: "N장 받을 차례" / "N장 갚을 차례" / "정산 끝"(쌍 기록 있고 잔액 0) / "주고받은 기록 없음".
  - `쏘기` 누르면 즉시 기록 생성(준 사람 = 나, 받은 사람 = 대상, 일시 = 지금) → 토스트 "OOO님에게 식권 1장 쐈어요" + `메모` + `되돌리기`(약 5초). `되돌리기`는 방금 기록을 **철회**한다(삭제 아님). `메모`는 그 기록의 메모 입력을 연다. 화면 잔액 즉시 갱신.
- "밥 살 사람" 보드: 빚진 사람(순잔액상 갚을 게 있는 사람) 목록.
  - 정렬: 갚을 총 장수 내림차순, 동률이면 이름 가나다순. 순위 숫자 표시, 1위만 빨강.
  - 각 행: 순위, 아바타, 이름(본인이면 `나` 태그), 사번, 총 장수, 그리고 갚을 상대 칩들(아바타 + 장수 배지, 아래 이름·사번).
  - `전체`: 모든 빚진 사람. `나`: 내 행(내가 갚을 상대들) + 나에게 빚진 사람들(칩은 나 하나만). 선택 상태는 URL 쿼리(`?scope=me`)로 유지 **(Claude 판단)**.
  - 빈 상태: "아직 밥 살 사람이 없어요" + 식권 쏘기 유도.
- 삭제된 회원도 잔액이 남아 있으면 보드에 나온다(이름 옆 회색 "삭제됨" 태그) **(Claude 판단)**.

### 4.3 이력 (`M · 이력`, `M · 기록 상세 시트`, `M · 철회 확인`, `D · 이력`)
- 상단 요약: "내 식권 잔액 ±X원" + 사람별 "OOO님에게 갚을 식권 N장" / "받을 식권 N장"(갚을 것 먼저, 그다음 받을 것, 각각 장수 내림차순).
- 필터
  - 검색어: 이름, 사번, **내 메모** 내용 부분 일치. 다른 사람의 메모는 검색 대상이 아니다(검색 결과로 남의 메모를 추론할 수 없게).
  - 기간: 시작일~종료일 선택. 기본값 = 오늘 기준 1개월 전 ~ 오늘.
  - 준 사람, 받은 사람: 회원 선택(삭제된 회원 포함), 기본 "전체".
  - 나만 보기: 내가 준 사람이거나 받은 사람인 기록만. 모바일은 스위치, 데스크톱은 체크박스.
  - 필터 상태는 URL 쿼리로 유지 **(Claude 판단)**.
- 목록: 최신순. 행 = 준 사람 → 받은 사람, 일자 `YYYY-MM-DD HH:MM`. 내가 관련된 행엔 `보냄`/`받음` 태그(모바일).
  - 철회된 기록: 지우지 않고 흐리게 + 취소선 + `철회됨` 태그 + "OOO님이 철회". 잔액 계산에서 제외. 철회는 되돌릴 수 없다(일반 회원 기준) **(Claude 판단)**.
  - 관리자가 수정한 기록: `수정됨` 태그.
  - 내 메모가 있는 행: 메모 토글 버튼. 펼치면 행 아래 잠금 아이콘과 함께 메모 표시. **기본 펼침.**
  - 목록 위 `메모 모두 접기` / `메모 모두 펼치기` 버튼으로 전체를 한 번에 전환. 개별 토글은 그 뒤에도 행마다 동작. 전체 접힘 상태는 브라우저에 기억 **(Claude 판단)**.
- 무한 스크롤 **(Claude 판단: 구체 동작)**
  - 처음엔 "기본 기간(최근 1개월)" 안의 기록을 보여주되, 한 번에 30건씩 커서(일시+id) 기반으로 로드.
  - 기간 필터를 사용자가 직접 바꾸지 않은 상태라면, 1개월 범위를 다 보여준 뒤 스크롤하면 그 이전 기록도 30건씩 계속 로드.
  - 사용자가 기간을 지정했다면 그 범위 안에서만 로드.
  - 로딩 표시 "이전 기록 불러오는 중", 끝이면 "처음 기록까지 다 봤어요".
- 내가 당사자인(준 사람 또는 받은 사람) 기록에만 동작이 있다. `철회`는 철회되지 않은 기록에만, 내 메모는 철회된 기록에도 쓰고 고칠 수 있다(개인 기록이라 "잘못 줘서 철회" 같은 메모가 필요) **(Claude 판단)**.
- 관리자가 기록의 준 사람·받은 사람을 바꾸면, 더 이상 당사자가 아닌 사람의 메모는 함께 지운다(본인이 고치거나 지울 수 없게 되므로) **(Claude 판단)**.
  - 모바일: 행 탭 → 기록 상세 시트(준 사람 → 받은 사람, 일시 읽기 전용, 내 메모 입력, `철회` / `메모 저장`).
  - 데스크톱: 행의 `메모`(토글/추가)와 `철회` 버튼. 메모 편집은 행 아래 패널에서.
  - 철회 확인: "이 기록을 철회할까요? / 잔액 계산에서 빠지고, 상대방도 내가 철회한 걸 볼 수 있어요." → `철회`.
- 메모: 기록당 사람당 1개(준 사람, 받은 사람이 각자 따로). 최대 200자 **(Claude 판단)**. 내가 당사자인 기록에만 달 수 있다 **(Claude 판단)**. 철회된 기록의 메모는 남고 볼 수 있다.

### 4.4 마이페이지 (`M · 마이페이지`, `D · 마이페이지`)
- 프로필 사진 변경: 이미지 파일 업로드(JPEG/PNG/WebP, 최대 5MB). 사진이 없으면 이름 끝 두 글자를 파스텔 원에 표시(색은 사용자 id로 결정).
- 이름 변경(1~20자) **(Claude 판단: 길이)**.
- 사번: 읽기 전용(잠금 아이콘). 변경은 관리자만.
- "비밀번호 변경" → `M · 비밀번호 변경` 화면: 현재 비밀번호, 새 비밀번호(4자 이상), 새 비밀번호 확인. 오류 메시지: "현재 비밀번호가 맞지 않아요", "새 비밀번호와 달라요", "4자 이상 입력해 주세요". 성공 시 토스트 "비밀번호를 바꿨어요".
- 로그아웃.

### 4.5 관리자 (`M · 회원 관리 (admin)`, `M · 회원 추가 시트`, `M · 회원 삭제 확인`, `M · 기록 관리 (admin)`, `D · 회원 관리 (admin)`, `D · 기록 관리 (admin)`)
- 관리자는 식권을 주고받는 당사자가 되지 않는다. `회원 관리` / `기록 관리` 두 화면만 접근(모바일은 상단 탭, 데스크톱은 상단 메뉴). 일반 화면 URL로 오면 회원 관리로 보낸다.
- 회원을 같은 사번으로 다시 추가하면 새 계정이다. 예전 계정의 기록은 "삭제됨" 표시로 남는다 **(Claude 판단)**.

**기록 관리**
- 목록: 모든 기록(철회 포함), 컬럼 `준 사람 | 받은 사람 | 일자 | 상태 | 수정·삭제`. 상태 = 정상 / "OOO님이 철회" / 수정됨.
- 필터: 검색(이름, 사번 — 관리자는 메모를 볼 수 없으므로 메모 검색 없음), 기간, 준 사람, 받은 사람. 무한 스크롤은 이력과 같은 방식.
- `기록 추가`: 준 사람, 받은 사람, 일시를 지정해 생성(과거 날짜 가능 — 기존 빚 옮겨 넣기 용도).
- 수정: 준 사람, 받은 사람, 일시. 수정하면 `수정됨` 표시(마지막 수정자·시각 저장).
- 삭제: 확인 후 실제 삭제(하드 삭제). 그 기록에 달린 개인 메모도 함께 삭제.
- 검증: 준 사람 ≠ 받은 사람, 둘 다 관리자가 아닌 회원.
- 관리자는 개인 메모를 볼 수 없다.
- 목록: 검색(이름/사번), 인원 수, 각 회원의 이름·사번·비밀번호 상태("초기 비밀번호"/"변경함"). 삭제된 회원은 목록에서 숨김.
- 추가: 이름, 사번 입력(사번 `maxLength=12`). 초기 비밀번호 `0000` 자동 설정, 안내 "처음 비밀번호는 0000으로 만들어져요".
- 수정: 이름, 사번. (모바일은 추가 시트와 같은 모양, 값이 채워진 상태. 데스크톱은 행 인라인 편집.)
- 삭제: 확인 팝업 "OOO님을 삭제할까요? / 로그인은 더 이상 안 되고, 주고받은 기록은 그대로 남아요." → 소프트 삭제.
- 사번 중복: 삭제되지 않은 회원 사이에서 유일. `admin`은 예약어로 일반 회원 사번 불가. 오류 "이미 쓰고 있는 사번이에요".
- 관리자 본인 비밀번호 변경: 관리자 헤더에 "비밀번호 변경" 링크 → 같은 비밀번호 변경 화면 **(Claude 판단)**.
- 관리자 계정은 삭제·사번 변경 불가.

### 4.6 공통 내비게이션
- 모바일(< 768px): 하단 캡슐 탭바 `홈 / 이력 / 마이`.
- 데스크톱(≥ 768px): 상단 바(로고, `홈 / 이력 / 마이`, 내 아바타·이름).
- 로그인 안 된 상태로 보호된 화면 접근 → `/login`.

## 5. 데이터 모델

```
users
  id              integer pk
  emp_no          text        -- 사번. 관리자 = 'admin'. 길이 제한 없음
  name            text
  password_hash   text        -- 단방향 해시
  is_admin        boolean
  password_changed boolean    -- false = 초기 비밀번호 사용 중
  avatar_path     text null
  deleted_at      timestamp null
  created_at      timestamp
  unique(emp_no) where deleted_at is null

transfers                      -- 식권 1장 = 1행
  id              integer pk
  giver_id        fk users
  receiver_id     fk users     -- giver_id <> receiver_id
  given_at        timestamp    -- 화면의 "일자"
  created_by      fk users     -- 쏜 사람 또는 관리자
  withdrawn_at    timestamp null
  withdrawn_by    fk users null -- 철회한 사람(준 사람 또는 받은 사람)
  edited_at       timestamp null -- 관리자 수정 시각("수정됨" 표시)
  edited_by       fk users null
  created_at
  index(given_at desc, id desc)

memos                          -- 개인 메모, 본인만 조회
  id              integer pk
  transfer_id     fk transfers (on delete cascade)
  user_id         fk users
  body            text         -- 최대 200자
  created_at, updated_at
  unique(transfer_id, user_id)
```

**순잔액 계산**: 철회되지 않은 기록만 사용. 쌍 (a, b)에 대해 `net = count(a→b) − count(b→a)`. `net > 0`이면 b가 a에게 net장 갚을 차례. 저장하지 않고 조회 시 계산(인원·건수가 작음).

**메모 접근 규칙**: 메모 조회·검색은 항상 `user_id = 현재 사용자` 조건으로만 한다. 관리자 API도 메모를 반환하지 않는다.

## 6. 기술 선택 (Claude 판단 — 기존 스캐폴드 기반)

- 기존 프로젝트: Next.js 16.4 App Router, React 19.3, Tailwind CSS v4, `cacheComponents: true`. 코드 작성 전 `node_modules/next/dist/docs/`의 해당 가이드를 읽고 따른다(AGENTS.md 지침).
- 변경은 Server Actions, 조회는 서버 컴포넌트 + 무한 스크롤용 서버 액션/라우트 핸들러.
- 실행 환경: 사내 PC/서버에서 Node 서버 한 대를 계속 켜두는 방식으로 가정(배포 대상 미정 — 클라우드로 옮기면 DB·사진 저장소 교체 필요).
- DB: SQLite 파일(`data/app.db`) + Drizzle ORM. 프로토타입이라 단일 서버 실행을 가정.
- 비밀번호 해시: bcrypt 계열(`bcryptjs`, 네이티브 빌드 불필요).
- 세션: 암호화 쿠키(`iron-session`), 비밀값은 환경변수 `SESSION_PASSWORD`. Next 문서의 "Authentication with Cache Components" 패턴을 따른다.
- 프로필 사진: `data/uploads/`에 저장, 라우트 핸들러로 서빙.
- 폰트: `next/font/google`의 IBM Plex Sans KR(본문), Black Han Sans(메인 숫자·로고·보드 제목에만).
- 시간대: Asia/Seoul 기준으로 표시·기간 계산.
- 시드: 최초 실행 시 `admin` / `admin1234!` 관리자 계정을 해시로 생성.
- 테스트: Vitest로 도메인 로직(순잔액, 상태 문구, 검증, 권한, 커서 페이징) 단위 테스트.
